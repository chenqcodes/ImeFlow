<h1 align="center">ImeFlow</h1>

<p align="center"><strong>让输入法跟随工作流。</strong><br>Let the IME follow your flow.</p>

写代码、敲命令、回消息，专注不该被一次次中英文切换打断。

ImeFlow 是面向 Windows 的输入模式自动切换工具。它感知当前应用和焦点所在的输入区域，在终端、代码编辑器、浏览器地址栏与聊天输入框之间，为你衔接合适的中英文输入模式，让切换融入工作流。

以 Rust 构建，通过 Windows UI Automation 识别输入场景，ImeFlow 将区域识别、规则匹配和输入法执行分开处理：你在 `rules.toml` 中定义目标模式，程序在焦点稳定后尝试执行，并在执行前核验输入目标。

- **细到输入区域**：同一个应用里，聊天框可以用中文，代码区和终端可以用英文。
- **通用默认与点选设置**：输入框中文，终端、地址栏、密码框和明确识别的代码区英文；可按软件、区域和控件标识手动覆盖。
- **保留手动选择**：同一输入区域处理一次，为手动切换留出空间；焦点变化时取消过期操作。
- **常驻托盘**：蓝色「中E」合字连接两种输入状态，提供自动切换开关、状态提示和日志入口。

## 运行

需要 Windows 10/11、PowerShell 7（`pwsh.exe`）及 Rust 工具链；本轮使用 Rust 1.98.1 验证。

- `01-build-and-run.cmd`：测试、构建、校验 PNG 资源，然后运行。
- `02-run-current.cmd`：运行最新且版本标记匹配的已验证构建。
- `03-open-logs.cmd`：打开程序使用的日志目录。
- `04-export-latest-log.cmd`：从最新正式会话导出关键日志。
- `05-verify-only.cmd`：仅测试、构建和资源校验。
- `06-release-package.cmd`：生成 `dist/ImeFlow` 发布目录。
- `07-install-local.cmd`：安装到 LocalAppData，创建开始菜单入口。

正式启动只允许一个实例。旧实例仍在运行时，退出托盘后再运行新版本；构建脚本不会杀进程。需要并行验证新代码时，可使用独立输出目录：

```powershell
./scripts/build-and-run.ps1 -TargetDir target/review-fixes -Lint
./scripts/verify-tooling.ps1 -Exe ./target/review-fixes/debug/imeflow.exe
```

02 会同时检查 `target/debug`、`target/release`、`target/review-fixes` 和 `target/rule-settings` 下的 debug/release 构建。版本来源为根目录 `build-id.txt`，程序的 `--version` 与构建标记使用同一份值。

## 规则与切换

规则引擎已接入自动切换主流程。程序启动时加载 `rules.toml`；焦点变化后，使用进程名和识别出的输入区域匹配**目标模式**，再由切换策略和输入法后端决定是否以及如何执行。规则中的目标不代表实际输入状态已经切换成功。

托盘右键选择 **通用默认设置**，即可调整所有软件的默认行为；选择 **点选输入区域设置**，点击目标输入框后设置手动覆盖。面板显示识别结果、匹配范围和当前规则来源；保存后自动加载，重新进入输入区域即可使用。目标没有唯一控件标识时，只提供软件或区域范围。保存前校验并备份旧文件，不会覆盖其他操作对配置的修改，也不会开启已关闭的自动切换。

高级用户仍可通过 **打开规则配置** 编辑文件，再选择 **重新加载规则**；加载失败时保留上一次有效规则。

按需求复制配置示例，见 [规则配置指南](docs/rules-guide.md)：应用默认中文、编辑器输入框中文与终端英文、浏览器配置以及完全不干预。

### 配置文件在哪里

程序优先读取 **`imeflow.exe` 同目录下的 `rules.toml`**，不存在时才读取当前工作目录中的文件。

- 本地开发：根目录 `rules.toml` 是新实例的默认模板；构建或启动时，仅在选中的构建目录没有配置时复制，保留面板里保存的修改。
- 发布包或已安装版本：通过托盘打开对应程序目录中的 `rules.toml`，保存后选择“重新加载规则”。本地安装脚本升级时保留已有配置，只在首次安装时复制默认规则；手动覆盖解压发布包时请自行保留原配置。

托盘“打开规则配置”会打开当前实例实际读取的文件。只修改项目根目录的文件，不会改变已有实例的配置。面板保存时自动加载并更新同目录 `rules.toml.bak` 备份；手动编辑则保存后从托盘重新加载。

### 规则示例

下面两条规则让 Cursor 的普通输入框使用中文、集成终端使用同一输入法的英文层：

```toml
[[rules]]
process = "Cursor.exe"
control = "edit"
mode = "native-chinese"

[[rules]]
process = "Cursor.exe"
control = "terminal"
mode = "ime-english"
```

`control` 可选值为 `terminal`、`address-bar`、`edit`、`password`、`code-editor`、`other`；省略时表示进程级默认规则。以上普通输入框和终端行为已经包含在新的通用默认中，只需为例外添加软件规则。

| 模式 | 含义 |
| --- | --- |
| `native-chinese` | 中文输入法的中文层 |
| `ime-english` | 同一个输入法的英文层 |
| `layout-english` | 美式键盘布局（ENG） |
| `passthrough` | 不干预输入模式 |

进程名精确匹配且忽略大小写；优先级为 **控件标识规则 > 软件区域规则 > 软件默认 > 通用默认 > 不干预**。未知软件也能使用通用默认。旧文件没有配置全局终端或密码框规则时，对应区域保留旧版不干预的兜底行为。字段拼写错误、无效模式或重复规则会导致加载失败，错误会说明原因。

### 切换流程与边界

流程为窗口/焦点事件、防抖、UIA 识别、规则匹配、稳定确认、纯策略决策、带焦点核验的 IME 执行、状态与统计回写。明确的 Monaco 代码结构优先于文件名关键词；聊天框使用 composer/prompt 结构区分。

同一区域只处理一次，保留手动切换空间。事务保存原始 HWND 和 UIA RuntimeId，在读取、等待之后以及按键/写入之前重新检查。焦点变化时取消；确认未产生副作用的失败可在复查预算内重新尝试。已经发键或可能写入的失败不自动重试，避免第二次 Shift 反转状态。

微信输入法结合 IMM 的 open 与 conversion 读取状态：open 关闭时，即使 conversion 仍保留中文位，也按推测英文处理。焦点确认后，同一焦点事件的原始模式读数需稳定至少 240ms；执行前再间隔 120ms 复核状态和输入法。目标已匹配则跳过，未知或变化中则暂缓；只有读数表明目标相反时才发送一次 Shift，中文与英文使用同一条路径，不叠加 IMM 写入和 Shift 回退。旧的目标记忆不参与微信输入法的切换判断，避免返回 terminal 时重复翻转，也避免在其他软件手动切换后沿用旧状态。

这些时间窗口用于过滤已观察到的焦点恢复/同步过渡，不保证覆盖所有输入法版本的同步延迟。稳定的 IMM 读数仍可能与真实输入状态不同，微信状态始终标为“推测 / 未确认”。执行前发现已匹配时按跳过记录，不计为切换，也不启动“刚按过 Shift”的防闪和手动覆盖逻辑。统计只累计已确认的自动请求。

托盘另有独立的只读状态观察：每 400ms 调度一次后台读取，连续两次稳定读数后更新图标，因此同一区域内手动切换后不必等到焦点变化。此路径不会发键、重放默认规则、修改配置或累计自动切换次数；切换焦点或自动执行期间产生的旧读数会被丢弃。

提示文字区分 `当前·中/英`、`推测·中/英（实时读取，未确认）` 和 `当前状态未知`；未知、等待决策、请求执行及执行尚未确认时，在没有实时读数的情况下使用中性图标，不提前点亮目标英文。提示仍保留目标和未确认状态。微信输入法的 IMM 读数可能不可靠，即使重复读到也只标记为推测，图标不能保证等于实际打字模式。按钮、侧栏列表项等导航控件不触发输入法切换；发键后取消的事务会清除旧模式记忆。

键盘钩子由专用线程串行管理，按需安装，空闲卸载；线程本身保留，避免停机与重新武装交错。UIA 接口与属性缓存请求按线程复用，每次焦点检查获取新快照。

### 输入法配置与兼容性

输入法自己的默认模式、按应用记忆、全局同步和中英文快捷键，会影响 ImeFlow。软件识别正确不等于切换结果正确；切换窗口后的短暂图标闪动也不等于最终输入模式错误。建议固定输入法设置后再测试，不要在对照过程中同时修改规则和输入法设置。

| 输入法 / 设置 | 使用条件与当前边界 |
| --- | --- |
| 微信输入法 | 配合 **默认输入状态 → 切换中英文对所有应用生效** 使用，并保留单独按 Shift 切换中英文。选项名称可能随版本变化；ImeFlow 不自动读取或修改该开关。关闭全局生效、改变 Shift 快捷键的组合尚未验证。 |
| 微信输入法的首次跨应用切换 | 本机在关闭 ImeFlow 自动切换后，仍观察到首次聚焦时中英标识短暂闪动；可能与上下文恢复或同步有关，具体内部机制未确认。最终状态以实际输入为准。 |
| 微软拼音 | 当前后端按可信 IMM 读数决策，保留原有切换路径；终端英文路径使用 Shift，请保留对应中英文切换快捷键。输入法版本、兼容模式及按应用设置变化后需重新验证。 |
| 其他中文输入法 | 目前有共用 IMM 后端，但没有逐一完成真实输入验证，不能据此宣称搜狗、小狼毫等均兼容。状态读取、快捷键或焦点恢复机制不匹配时，先关闭自动切换或将对应软件设为 `passthrough`。 |
| Windows“允许我为每个应用窗口使用不同的输入法” | 此系统选项与微信输入法的“对所有应用生效”不是同一个开关；输入法选择与输入法内部中英文模式应分别核对，不要求用户统一更改 Windows 设置。 |

首次使用或升级输入法后，建议做以下对照：

1. 关闭 ImeFlow 自动切换，记录输入法版本、全局/按应用设置和中英文快捷键，观察两个软件之间与同一软件不同输入区之间的原生行为。
2. 微信输入法勾选“对所有应用生效”，保留 Shift 切换，等待状态稳定后启用 ImeFlow。
3. 在 terminal、网页输入框、地址栏、聊天输入框之间往返数次；重复返回同一 terminal 应保持英文，进入中文输入框应能中文输入。测试字符不要在 terminal 按回车执行。
4. 在同一区域手动切换，确认不会立即被切回；再到另一个软件手动切换并返回，确认不会依据旧记忆跳过必要切换。另检查首次聚焦和快速来回切换。
5. 如有异常，提交输入法/Windows/目标应用版本、相关设置、复现步骤及对应时间段的 debug 日志。日志读数与托盘图标都不能替代实际输入验收；分享前检查并删除不希望公开的信息。

本次自动回归覆盖 open 关闭但中文位残留、重复返回 terminal/地址栏、跨应用手动模式变化、状态稳定窗口及发键前后端变化。**这些测试不代表所有输入法、版本和设置组合已经通过真实打字验收。**

## 日志与诊断

默认目录为 `%LOCALAPPDATA%/ImeFlow/logs`；`IMEFLOW_LOG_DIR` 可指定其他目录，程序、托盘和脚本共同遵守它。

### 日志级别

无配置时默认 `warn`，发布版本只记录警告和错误，以及每个会话的日志配置头。本地开发可将 `.env.example` 复制为项目根目录的 `.env`：

```dotenv
IMEFLOW_LOG_LEVEL=debug
```

支持 `off`、`error`、`warn`、`info`、`debug`、`trace`；修改后重启生效。优先级为 `RUST_LOG` 环境变量、`IMEFLOW_LOG_LEVEL` 环境变量、`--debug` 参数、`.env`、默认 `warn`。`RUST_LOG` 还可使用模块级过滤，例如 `imeflow=debug`。

程序先查找 exe 同目录的 `.env`；debug 构建还会回退到开发项目根目录。release 构建不会读取开发目录或当前工作目录的 `.env`，需要诊断时可在 exe 旁显式配置。`.env` 已加入 Git 忽略，打包与安装脚本不复制它；仓库仅保留 `.env.example`。文件只读取 `IMEFLOW_LOG_LEVEL`，不执行变量展开或其他配置。

debug 日志包含焦点事件、区域分类依据、目标模式、实际观测的可信度、模式记忆、跳过原因、切换事务及取消后的记忆失效。常规日志不记录 UIA 控件名称、聊天内容或祖先节点文本。Shift 记录仅在原有的按需监听或显式 `--trace-keys` 期间产生；开启 debug 不会额外安装键盘钩子，也不记录输入的字母。

### 日志文件

- `session-*.log`：正式会话独立日志，重启后保留。
- `latest.log`：当前正式会话的兼容入口，仅获得单实例所有权后更新。
- `diagnostic-*.log`：资源校验和探针独立日志，不覆盖正式会话。
- `latest-key.log`：04 导出的关键日志。

`--version` 不初始化日志；`--check-assets` 不安装输入钩子、不更改 IME、不写统计。`--probe-focus`、`--probe-ime` 用于读取诊断；TSF global compartment 只能作为全局诊断信号，不能证明目标控件的实际输入模式。`--probe-shift`、`--verify-switch`、`--trace-probe` 会进行输入或切换，仅在有意测试时使用。

## 验证

托盘 **规则管理 / 导入导出** 可按软件筛选、修改或删除覆盖，预览并应用常用软件预设，导入、导出和恢复上一份配置。点选设置支持捕获位置边框提示及匹配说明。具体行为与限制见 [规则指南](docs/rules-guide.md)。

```powershell
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
```

测试覆盖分类、规则、焦点 gate、切换策略、副作用与重试边界、日志隔离、单实例和真实 Windows 钩子线程启停。自动检查不能替代微软拼音/微信输入法在目标应用中的实际打字验收。

## 许可证与隐私

项目代码和仓库内绘制的图标采用 [MIT 许可证](LICENSE)。第三方 Rust 依赖保留各自许可证；发布包附带依赖许可文本。

ImeFlow 在本机识别前台应用和 UI Automation 控件来选择输入模式。规则、统计与诊断日志保存在本机；正常运行的日志不记录键入字符或聊天正文。显式诊断命令可能输出当前控件名称及输入区域信息，分享日志前请检查内容。

`.env`、日志、规则备份、`.local` 本机笔记、编辑器工作记录和构建产物不纳入源码版本控制。提交问题时请提供最小复现步骤，不要直接上传个人完整配置或整个日志目录。
