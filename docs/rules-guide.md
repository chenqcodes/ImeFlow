# 配置输入规则

优先使用托盘右键菜单里的 **通用默认设置** 和 **点选输入区域设置**。一般不需要手写 `rules.toml`；高级配置仍可通过 **打开规则配置** 编辑，再选择 **重新加载规则**。

## 通用默认

新配置对所有软件生效，无需逐个添加进程名：

| 输入区域 | 默认目标 |
| --- | --- |
| 普通输入框 | 中文 |
| 终端 | 当前输入法的英文状态 |
| 浏览器地址栏 | 当前输入法的英文状态 |
| 密码框 | 当前输入法的英文状态 |
| 明确识别的代码编辑区 | 当前输入法的英文状态 |
| 其他 / 无法识别的区域 | 不干预 |

代码区目前依赖明确的 Monaco 结构；未识别出的编辑器不会仅凭文件名、窗口标题或输入内容被当作代码区。搜索、重命名等通常仍是普通输入框，不能保证单独识别用途。按钮、菜单、侧栏列表项等导航控件始终不触发切换。

保留的常用预设只补足 `other` 区域：微信（WeChat / Weixin）、ChatGPT、记事本默认中文；Windows Terminal、PowerShell、pwsh、cmd、conhost 默认英文。这些规则不会覆盖已经识别的密码框、终端或代码区。浏览器和 Cursor / VS Code 的已识别区域直接使用通用默认。

在 **通用默认设置** 中选择一个区域和模式，再点击 **保存并生效**。**恢复推荐默认** 只恢复当前选中的区域。

```toml
[defaults]
edit = "native-chinese"
terminal = "ime-english"
address-bar = "ime-english"
password = "ime-english"
code-editor = "ime-english"
other = "passthrough"
```

## 点选设置

1. 选择托盘菜单 **点选输入区域设置**。
2. 点击目标输入框，等待区域稳定。捕获期间暂停自动切换；关闭面板或按 Esc 可取消。
3. 面板显示软件、识别出的区域、控件标识（如果有）、当前目标及规则来源。目标捕获后锁定，点击设置面板不会把目标换成面板自身。
4. 选择生效范围及中文、英文或不干预，点击 **保存并生效**。
5. 回到目标输入区域，新的规则在焦点重新进入后使用。

可选范围：

- **此软件中相同标识的控件**：只有控件具有 AutomationId，且点选时该标识在当前窗口内唯一，才提供此选项。规则匹配进程名、区域类型、AutomationId、类名和控件类型；同一软件其他窗口中相同标识的控件也会匹配。软件更新可能改变标识，需要重新点选。
- **此软件的同类区域**：例如仅改变该软件的普通输入框，保留终端等其他区域的规则。
- **整个软件**：作为软件默认；更具体的控件和区域规则仍优先。
- **所有软件的此类区域**：修改对应的通用默认。

无法获取唯一标识时，不会提供控件标识范围。无法读取输入目标或点到导航控件时，面板继续等待。不会保存坐标、运行期 RuntimeId、窗口标题或输入内容。

**删除此范围的覆盖** 只删除当前范围的规则，然后回退到下一层。选择全局范围时，此按钮变为 **恢复推荐默认**。设置整个软件不干预时，已有的更具体规则仍有效；如需完全不干预，也要删除或修改这些规则。

## 优先级与高级配置

### 规则管理、匹配说明与高亮

托盘菜单 **规则管理 / 导入导出** 打开规则列表，可筛选所有规则、通用默认或某个软件。选中规则即可修改模式、删除覆盖；通用默认提供“恢复此项推荐默认”。新增规则使用“点选检查 / 新增”。

点选面板捕获输入区域后，在可读取位置时闪显边框 3 秒，不抢焦点、不拦截点击。目标窗口移动、切走、重新点选、保存或关闭面板会提前清除。边框是捕获时的位置提示，不持续追踪页面内部滚动；无法读取位置时仍可查看区域信息。点击 **匹配说明** 查看命中范围、规则来源、相关默认及优先级。说明是规则试算，不代表输入法切换已成功。

规则管理提供三组可选预设：浏览器、开发工具、聊天与记事本。先预览再应用；已有同范围规则保持不变，新增区域规则可能优先于已有软件默认或通用默认，控件规则仍优先。预设应用后成为普通规则，可逐项修改或删除。

**导入预览** 校验 TOML 并列出新增、删除和修改；点击“应用预览”才整体替换配置。导入不是合并。**导出当前** 将当前磁盘配置保存到所选文件。**恢复上一份预览** 读取 `rules.toml.bak`，先查看差异再应用；恢复时当前配置也会成为新的备份，因此可撤回这次恢复。备份仅保留上一份，每次成功保存都会更新。

预览期间切换规则、筛选或刷新会取消预览。其他窗口或外部编辑器修改了配置时，旧预览会拒绝覆盖，刷新后重新预览即可。无效导入不会改变当前文件或运行中的规则。

**控件标识规则 > 软件区域规则 > 软件默认 > 通用默认 > 不干预。** 显式“不干预”同样具有这一优先级。

例如只让某个软件的普通输入框默认英文：

```toml
[[rules]]
process = "example.exe"
control = "edit"
mode = "ime-english"
```

进程名精确匹配、忽略大小写，不支持路径或通配符。省略 `control` 表示软件默认。模式包括 `native-chinese`（中文）、`ime-english`（同一输入法英文）、`passthrough`（不干预）、`layout-english`（ENG 美式键盘，高级选项）。

旧配置仍可读取。没有显式配置 `defaults.terminal` / `defaults.password` 时，相应区域保留旧版不使用软件默认兜底的行为；已有软件区域规则仍优先。不会为了升级自动覆盖旧配置。

规则指定的是目标，不代表输入法已成功切换。原有输入法后端限制仍然存在，例如终端中文目标可能无法由现有终端执行路径完成，微信输入法的已请求状态也不等于实际确认。

在同一输入区域手动切换中英文，不会改写默认规则，也不会由图标观察逻辑切回默认。托盘后台只读观察当前状态，连续两次稳定读数后更新图标；读数不可靠时提示“推测 / 未确认”，读不到时使用中性图标并提示“当前状态未知”。离开后重新进入输入区域，仍按配置的默认规则处理。

## 保存、配置位置与恢复

面板修改当前实例实际读取的 `rules.toml`，保留其他规则和文件注释；更新前校验，写入同目录临时文件后替换，并自动加载。上一份配置备份为同目录 `rules.toml.bak`，每次成功保存更新一份备份。文件被其他操作修改后，旧面板拒绝覆盖，请重新打开设置或重新点选。

加载失败时，上一次有效规则继续生效。保存不会自动开启已暂停的自动切换。

程序优先读取 `imeflow.exe` 同目录配置，不存在时读取当前工作目录配置。开发构建与启动脚本只在目标目录没有配置时复制项目默认，避免重启覆盖面板中保存的设置。项目根目录 `rules.toml` 是新实例的默认模板；要修改已有实例，请通过其托盘打开实际配置。
